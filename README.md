# 口袋里的玩具 —— 八音琴（EasyInput V2.0 / ESP32-S3）

一台能塞进口袋的小琴：**可以玩、可以学、可以创作**。

- 课程：第七期 AI 硬件基础训练营 · 第8课毕业大作业
- 方向：**方向二 · 从零开始实现自己想做的项目**（板子是课程提供的载体，项目是自己构思的）
- 作业文档（含演示视频）：https://ucn299x5d3ob.feishu.cn/wiki/WMOAwUg5Uil7RRkwQ5RcRkOQnVf

## 它长什么样

一块 EasyInput V2.0（ESP32-S3）开发板 —— 8 个按键（8 个音）、1 个 EC11 旋钮、5 颗 WS2812 灯、1 个 I2S 喇叭 —— 长成一个「文件夹式」的顶层结构：

```
主目录（开机默认；语音「请选择模式」＋ D1~D4 亮）
 ├─ S1 试听 ── 内置曲库，最多 5 首
 ├─ S2 自弹 ── 弹奏 ＋ 记谱（记「按了哪个键 ＋ 隔了多久」，即简谱）
 ├─ S3 游戏 ── 网页跟弹闯关
 └─ S4 回放 ── 放自己弹的（持久化在 flash）
任何场景：长按旋钮 ≥5 秒 → 回主目录
主目录转旋钮 ＝ 调灯亮度（掉电记忆）｜ 其它模式转旋钮 ＝ 调音量
```

## 目录结构

| 目录 | 内容 |
|-|-|
| `firmware/` | 固件（ESP-IDF 工程）：`main/` 源码，`host_test/` 宿主测试（ctest） |
| `web/` | 网页端：单文件 `index.html`（曲库管理 ＋ **自己编曲** ＋ 8 音跟弹闯关，走 Web Serial） |
| `tools/` | 生成语音语料 / 音色的脚本与素材、串口日志工具 |
| `docs/` | 需求与决策记录、变更与会话记录（「资料先行」的证据） |

## 编译

```bash
. $IDF_PATH/export.sh          # ESP-IDF 5.5
cd firmware && idf.py build
```

## 烧录（⚠️ 有个坑）

```bash
esptool --chip esp32s3 -p <PORT> -b 460800 write_flash \
  0x0      bootloader/bootloader.bin \
  0x8000   partition-table.bin \
  0x10000  ota_data_initial.bin \
  0x20000  easyinput_piano.bin \
  0x9D8000 voice_prompts.vpmt
```

⚠️ **语音是单独一份 `voice_prompts.vpmt`，必须写到 `rec` 分区 offset `0x9D8000`。**
只烧主程序会出现「**静默无语音**」——听不到任何提示，但也不报错，很容易误判成硬件坏了。

## 宿主测试

```bash
cd firmware/host_test
cmake -B build-host && cmake --build build-host && ctest --test-dir build-host --output-on-failure
```

当前 **15/15 全绿**（含一条「钢琴化音色」的客观回归用例：起音为 0、不削顶、含偶次谐波、
高次分音落在被拉伸的频率上、双段衰减——把这条用例跑在**旧采样**上会直接断言失败）。

## 网页端

```bash
cd web && python -m http.server 8765
# 浏览器打开 http://127.0.0.1:8765/index.html
```

需要支持 Web Serial 的浏览器（Chrome / Edge）；页面里点「连接键盘」选 USB 串行设备。

**网页自测（可复跑，不用装任何东西）**：打开 `http://127.0.0.1:8765/index.html?selftest=1`，
页面会自己跑一遍网页侧自测（判定 / 连按 / 得分 / 出站协议 / 滑块与各按钮的出站命令 / 帧率折算 / 日志上限 /
**简谱解析 / 我的歌单 / 推给板子**），结果写在左上角状态栏与浏览器控制台（当前 **56/56 全绿、0 控制台报错**）。
它用**串口桩**模拟板子，**只验网页侧**：验的是"网页发出的命令对不对"，**不代替真机验收**。

## 硬件红线（别踩）

| ❌ 错误 | ✅ 正确 |
|-|-|
| S1 ＝ GPIO1 | S1 ＝ GPIO2 |
| S5 ＝ GPIO0 | S5 ＝ GPIO1 |
| S6 / S7 ＝ GPIO5 / 6 | S6 / S7 ＝ GPIO6 / 7 |
| GPIO8 只是灯的开关 | GPIO8 是灯＋麦＋喇叭的共享总电源 |
| 发黑帧 ＝ 关电源 | 黑帧只熄灯，不动 GPIO8 |
| BOOT 要按住再上电 | 开机状态下短按一下就能进下载模式 |
| GPIO26~37 可用 | 那是内存总线，绝对禁用 |

## 网页设置 ⇄ 板子：谁能同步、谁只在网页生效

按用户要求把网页每个功能逐个排查了一遍。依据是固件 `firmware/main/host/host_link.c` 的命令解析表
＋ 网页 `web/index.html` 里每个控件的发送点。

| 网页上的功能 | 会同步到板子吗 | 走什么命令 / 说明 |
|-|-|-|
| 灯亮度滑块 | ✅ 同步（写 NVS，掉电记忆） | `brightness`；板子回 `state.bri`，两边显示同一个数 |
| 音量滑块 | ✅ 同步（写 NVS，掉电记忆） | `volume`；板子回 `state.vol` |
| 开机语音：重播 / 恢复默认 | ✅ 同步 | `voice_replay` / `voice_default` |
| 开机语音：导入我的语音 | ✅ 同步（写 flash，开机优先播它） | `voice_begin` → `voice_data`（分块 base64）→ `voice_end` |
| 曲库：新增 / 替换 / 删除 / 试听 / 刷新 | ✅ 同步（写 `rec` 分区 flash，持久） | `song_add` / `song_del` / `song_list` / `song_play`（v2 协议） |
| **自己编曲：存入板子槽位** | ✅ 同步（写 flash，持久） | 同上 `song_add`，写完自动 `song_play` 试听 |
| **自己编曲：网页试听** | ❌ 不同步（**故意**） | 纯浏览器合成、不碰板子 —— 没接板子也能听自己写的曲子 |
| **自己编曲：存进「我的歌单」** | ❌ 不同步（**故意**） | 存在浏览器本地、不限首数；板子没有"歌单"这个概念 |
| 游戏通关的曲子 → 板子回放池 | ✅ 同步（板端记谱 + 持久化） | 开局 `record:1` → 通关 `record:0` → 板子落槽 |
| **连板子后回读真实状态（板 → 网页）** | ✅ 本轮新增 | 连上后自动 `ping`（回 `hello`+`state`）＋ `song_list`，滑块与曲库显示的是**板子的实际值**而不是网页默认值 |
| 音源（板子响 / 电脑响） | ➖ 不需要同步 | 网页自己的发声开关，板子没有对应状态 |
| 背景音开关 / 游戏玩法 / 简单专家速度 | ➖ 不需要同步 | 纯网页显示与判定设置 |
| **开机提示音 开 / 关** | ❌ 固件还没有 | 现在只能「换语音」或「恢复默认」，没有总开关 —— 要加得改固件（下一步） |
| 板子曲库槽数量 | ❌ 固定 5 槽 | `SONGP_SLOTS = 5`（`rec` 槽 0~4）；想放更多要改固件分区使用（下一步） |

## 已知限制与下一步

四项历史遗留的闭环情况。口径说清楚：**能自动化的都已自动化证明；需要耳朵 / 需要板子的，仍要真机**。

| 项 | 状态 | 证据（可复跑） | 仍需人 / 板子 |
|-|-|-|-|
| 板子按键连按 → 网页跟手性 | **网页侧已修并验证** | 根因：判定要求"音符已落线"，**按对但音符还没落线会被直接丢弃**（连按第二下常被吞，小星星开头连着两个"哆"最明显）。改为**按对即命中**（音符瞬移到判定线再爆开）；页面自测 **56/56**、真实键盘连按 `1,1,5,5,6,6` → 进度 `0/42→6/42` 无一次被吞 | 板子 → 网页这段**串口时序**要接板再测（可能是串口积压，不是判定） |
| 游戏端联动终验 | **网页侧协议已验** | 自测断言：开局发 `record:1`、通关发 `record:0`、400 ms 后 `play:0`；`song_add / song_del / song_list` 字段正确 | 板子是否真的照做（发声 / 亮灯 / 落回放池）待上板 |
| 8 键音色更像钢琴 | **已重做，客观性质已验** | 音符采样由"音乐盒式泛音"改为**钢琴式泛音堆栈 ＋ 轻微失谐 ＋ 双段衰减 ＋ 明亮起音**；新增客观回归用例：新采样通过，**旧采样在该断言处直接失败**（判据有效） | **听感**只能人耳确认；真机再听一遍 |
| 网页界面美化 | **已做** | 底色辉光、画布外发光、统计改胶囊、新增键位图例（1哆…8高哆）、"下一步按哪键"高亮提示条、焦点环、减弱动效适配 | 观感仍可继续打磨 |
| 游戏规则：按错即结束 | **已改并用浏览器实测** | 原来按错只闪红、可以一直试到按对；现在**按错立刻结束本局**（💥 本局结束 ＋ 弹窗，`record:0` 丢弃本次记谱**不落回放池**）。实测：按错后进度停在 `0/42`，再按正确的键也**不推进**。注：`docs/八音琴-真机验收清单.md` 的 T25 本来就是这么写的——**是代码没做到，现在对齐了** | 真机上再按一遍确认手感 |
| 游戏规则：落线超时也结束 | **已加（第二轮追加）** | 音符落到判定线后**不再无限等你按**：`NOTE_HOLD_LIMIT_MS = 2500ms` 内没按对 → 同样 💥 本局结束（复用同一条 `gOver()` 流程，也是 `record:0` 丢弃记谱）。判据抽成 `checkNoteTimeout()`，自测直接调它断言 | — |
| **用户自己加歌（想加很多首）** | **已给路径** | 板子只有 5 个曲库槽（`SONGP_SLOTS=5`），所以把"歌库"放在**网页本地「我的歌单」**（不限首数）＋**简谱输入**（`1~7`=哆~唏、`8`=高哆、`n:2`=占两拍、`-`=延音）；写进板子走既有 `song_add`（写 flash 持久）并自动让板子试听；自编曲也合并进**游戏选歌**。自测 **M/N/O/P 共 14 条**覆盖解析、本地库、游戏合并、推板子命令、网页试听不发命令 | 真机确认"存完断电重启板子还在 ＋ 试听模式按 S1~S5 能听到" |
| **「开机提示音 开 / 关」总开关** | **固件不支持** | 现在只有「换语音 / 恢复默认」（两者都已能同步到板子）；要加总开关需改固件（新命令 + NVS 持久）→ 列为下一步 | — |
| 网页 ⇄ 板子 实时同步 | **已加"看得见"的确认** | 先分清是哪一端的问题：**固件侧实测是好的** —— 直接发 `brightness=200` / `volume=40`，板子回的 `state` 里 `bri` `8→200`、`vol` `60→40`（`ping` 也有回应）。网页侧新增：拖滑块 → 与板子回传值比对 → 亮「**✅ 已同步（板子音量 = N）**」或「**⚠️ 板子没跟上**」（十有八九是没连上或串口被占）；**没连板子时命令发不出去也会明确提示**；连上后还会主动回读板子真实状态 | — |
| 游戏画面"跑道"与宽度 | **已按你的要求改** | 页面改**三栏**（说明文字搬到左右两栏）；画布宽 `480→960` 逻辑像素（**屏幕宽度约为原来 2 倍**）、高 `880`、判定线 `640`；尺寸由 `gFit()` 同时满足"中栏宽度 + 视口高度"（避免拉伸变形），窄屏（<900px）自动把两栏收到下面 | 仍可继续微调判定线位置与下落时长 |

- 公网托管未做（Web Serial 只能在 https 或本机环境用），先用静态演示 ＋ 录屏。
- **蓝牙（BLE）代替数据线？能做到，但不是这一轮的事。** ESP32-S3 芯片本身支持 BLE，但现在的"板子 ⇄ 网页"通道跑在
  **USB-Serial/JTAG（Web Serial）** 上；换成蓝牙要**两边都改**：固件加一个 BLE GATT 服务、把同一套换行 JSON 协议搬过去，
  网页改用 **Web Bluetooth API**（同样要求 https 或本机环境，且部分浏览器/系统对它的支持有限）。
  属于**独立的中等规模工程**，所以列为下一步；本轮先把"有线情况下的实时同步"做对。
