## 二、逐项做了什么 · 证据 · 复跑方法

### ① 板子连按 → 网页跟手性

**根因（这是真正的 bug，不是"感觉"）**：网页判定原来要求「音符已落到判定线」才接受按键；
**按对了、但音符还没落线，这一下会被直接丢弃**。小星星开头连续两个「哆」——
按完第一个，第二个音符刚出生（要 700~1600ms 才落线），第二下按下去就**白按**。

**改动**（[web/index.html](file:///E:/easyIntput/easyinput-piano/web/index.html)）：
- `gameOnKey()`：**按对即命中**——不再要求落线；命中时把音符"瞬移"到判定线再爆开（视觉不突兀、手感立刻有反馈）。
- 按错的判定保留：**只有已落定 / 进入 150ms 提前窗口才算误按**（过早的手滑不罚）。
- 新增按键诊断字段 `r=hit|miss|ignored|release|idle`——以后"按了没反应"一眼可分：
  是**串口没到**，还是**判定被吞**。
- 原始 JSON 不再为每个按键重复打印（`[KEYDBG]` 已覆盖），日志面板保留上限 200 行。

**证据**：
- 页面自测 **30/30 全绿、0 控制台报错**（真实浏览器）。
- **真实键盘连按实测**：按 `1,1,5,5,6,6` → 进度 `0/42 → 1/42 → 2/42 → 3/42 → 4/42 → 5/42 → 6/42`，
  **每一次都推进，没有任何一次被吞**（改前第二下必吞）。

**复跑**：`cd web && python -m http.server 8765` → 打开 `http://127.0.0.1:8765/index.html?selftest=1`

**仍需你**：接板后连按，看 `[KEYDBG]` 的 `gap=` 与 `r=`——若 `gap` 很大而 `r=hit`，
说明瓶颈在**串口积压**（板子侧），不在判定；那属于下一步要改的固件发送策略。

### ② 游戏端（网页 ＋ 板子）联动终验

**做法**：把"联动契约"变成**入库断言**（以前只临时跑一次、脚本没留下，所以数字无从复核）。
用**串口桩**模拟板子，断言网页侧每次该发的命令都发对了：
- 开局 → 发 `record:1`（板子开始记谱）
- 通关 → 发 `record:0`，**400ms 后**自动发 `play:0`（板子回放刚弹的曲子）
- 曲库 → `song_add`（v2 / slot / name / notes）、`song_del`、`song_list`

**证据**：自测里的 A2 / E3 / E4 / G1 / G2 / G3 六条断言全绿（含 400ms 延时的真实异步等待）。

**仍需你**：接板打通一局，确认板子**真的**记了谱、回放了、并落进回放池（`docs/八音琴-真机验收清单.md` 的 T24~T28）。

### ③ 8 键音色更像钢琴

**先纠了一个认知错误**：按 S1~S8 走的是**预生成的 PCM 采样**（`firmware/main/audio/samples/note_*.raw`），
**不是**现场合成那条分支（那条只用于音量反馈音）。所以改的是**采样生成器**
（[tools/gen_note_samples.py](file:///E:/easyIntput/easyinput-piano/tools/gen_note_samples.py)），不是 `audio_click.c`。

**改动**：
- 泛音：音乐盒式的 6 个谐波 → **钢琴式 8 个分音**，幅度 ≈ 1/n^1.3；
- **轻微失谐（inharmonicity）** `B = 5e-4`：`f_n = f0·n·√(1+B·n²)`（模拟钢琴弦刚度，高次分音被"拉伸"）；
- 衰减：单一指数 `3.2` → **双段衰减**（快速段 +7.0，权重 0.45；基座 2.6）；
- 新增 **明亮起音瞬态**（10~16 次分音，τ=10ms）；
- **防 click 的设计原样保留**（5ms 余弦起音窗 + 120ms 余弦释放窗）。
- 重新生成 7 个 `note_*.raw`（每个 54400 B，**总大小不变**）。

**客观证据**（因为声音好不好听是主观的，所以只断言"波形是否具备钢琴特征"，并**证明判据有效**）：
新增 [piano_timbre_tests.c](file:///E:/easyIntput/easyinput-piano/firmware/host_test/piano_timbre_tests.c)，5 条断言 —— 实测输出：

```
attack: x0=0 max|Δ|(5ms)=4306          ← 起音为 0、无阶跃（不 click）
peak=27851 last=0                       ← 不削顶（<32767），结尾收干
A1=2545 A2/A1=0.299 A3/A1=0.079         ← 含明显偶次谐波（纯三角波此处≈0）
partial4/5/6: ratio=4.50 / 7.70 / 12.09 ← 能量落在「被拉伸」的频率上，不是理想整数倍
decay early=5.02/s late=2.93/s ratio=1.71 ← 前快后慢（单一指数则两者相等）
```

**判据有效性的自证**：把**同一条用例**跑在**旧采样**上 → 在失谐断言处直接 abort（`exit=134`）。
说明这条用例**真的能分辨新旧**，不是恒真断言。

**仍需你**：**用耳朵确认**。真机上弹一遍 S1~S8，听是不是更"像钢琴"、有没有破音。
（另注：S8 是 do 采样升八度变速播放；多键同按走软限幅。）

### ④ 网页界面美化

**改动**（纯 CSS/HTML + 画布细节，不动游戏逻辑）：
- 底色加青绿辉光（整页不再是死黑）；画布 `.stage` 加外发光与多层阴影；
- 统计数字改成**胶囊小药丸**（进度 / 连击 / 得分）；
- 新增**键位图例**（`1 哆 2 唻 … 8 高哆`）——帮玩家建立"按键 ↔ 音"的映射；
- 「下一步按哪个键」做成**高亮提示条**（这是全屏最该一眼看到的信息，原来只是一行灰字）；
- 按钮 hover / active / `:focus-visible` 焦点环；`prefers-reduced-motion` 减弱动效适配；
- 画布加**音轨分隔线**（原来只有底纹，8 条轨边界含糊）。

**证据**：浏览器实测截图 —— 深色竖画布、三颗统计胶囊、8 个键位图例、「下一步」高亮提示条**都在位**，
**无重叠、无不可见文字、无布局破版**；控制台 **0 error / 0 warning**。

## 四、诚实清单：本轮**没有**证明的事

1. **没有上板**（板子不在 COM3/COM4）→ 所有真机现象都**未复验**。
2. **跟手性的真机手感未验**：网页侧判定已修，但"板子 → 网页"的**串口时序**（是否有积压 / 丢事件）没接板测过。
3. **音色"像不像钢琴"未验**：只证明了波形客观特征（谐波堆栈 / 失谐 / 双段衰减 / 不削顶），**听感是主观的**。
4. **游戏联动只见网页出站命令**：板子有没有真的照做（发声、亮灯、落回放池）没验。
5. **界面观感**：只能说"无破版、元素在位、0 报错"，好不好看要你自己看。
6. 本轮固件**未烧录**：板上跑的还是 R21 期固件（R22 改的只是自报版本串，也已编译验证但未上板）。
